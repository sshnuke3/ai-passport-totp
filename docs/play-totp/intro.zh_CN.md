TotpPassport · AI Passport 玩法
===============================

把 AI Passport 变成一个离线的两步验证码硬件令牌。

不是「把手机上的 App 搬到小屏」，而是回答一个具体问题：
你的手机在充电、在放兜里、或者干脆没电的时候，
登录需要二次验证的网站怎么办？

TotpPassport 的答案是——**不联网也能出码**。
它把所有密钥存在设备本地，按需短暂连一下 Wi-Fi 校准时间，然后立刻断开。


一、它解决什么问题
------------------
  1. **物理隔离手机攻击面**。钓鱼网站骗走你手机上那个 Authenticator，
     骗不走桌上这个没有任何无线能力的小盒子。
  2. **不掏手机**。按键三下就出码，适合已经在工位上、手边有事的时候。
  3. **断网可用**。TOTP 本身不需要网络。设备只在开机校时和录入账户时用 Wi-Fi，
     平时是彻底离线的。
  4. **丢设备可恢复**。加密备份导出，配合自设备份口令，
     换一台设备能完整恢复全部账户。


二、它长什么样
--------------
主界面是账户列表，每行左边是账户名、右边是当前验证码。

    ┌────────────────────────┐
    │ 已校时 · 3 个账户        │  ← 状态行：时间源 + 账户数
    ├────────────────────────┤
    │ ● 1. GitHub             │
    │        4 8 2 9 1 5      │  ← 最后 5 秒变红
    │ ● 2. Cloudflare        │
    │        1 1 0 2 4 8      │
    │ ● 3. ProtonMail         │
    │        9 0 4 4 5 6      │
    │   + 录入账户            │  ← 动作行
    │   重新校时              │
    │   设置 PIN 锁           │
    ├────────────────────────┤
    │ OK 查看 · 上下选择      │
    └────────────────────────┘
        底部是设备自带的草地装饰

按 OK 进详情页，验证码放大到 44px，下方是剩余时间进度条：

三、支持什么
-----------
  · 算法：SHA1 / SHA256 / SHA512（自动从 otpauth 链接识别）
  · 位数：6 位与 8 位（自动识别，也支持 7/9/10 位）
  · 周期：30 秒与 60 秒（自动识别）
  · 账户数：最多 24 个
  · 密钥长度：最长 64 字节 base32（覆盖 SHA-512 的长密钥场景）


四、它明确不做的事
------------------
  · **不做企业级安全宣称**。这台设备是透明外壳，密钥在 flash 里是明文。
    物理拆芯片可以把密钥读出来。TotpPassport 防的是手机端的软件攻击面，
    不是硬件提取。这是设计取舍，不是缺陷。
  · **不做云同步**。密钥不上传任何服务器，包括你的。
  · **不做 NFC 录入**。硬件没有 NFC 模组。
  · **不做多语言界面**。中文单语。


五、和其他工具的区别
-------------------
  · 对比手机 App：多了一层物理隔离，少了云端备份（所以我们做了本地加密备份）。
  · 对比 yubikey：便宜得多，但**没有 U2F/FIDO 功能**，只能做 TOTP。
    需要 FIDO 硬件密钥请买 yubikey。
  · 对比其他 AI Passport 玩法：这是少数「实用工具」方向的玩法。
    设备的能力（无触屏、240×320、三键）恰好匹配 TOTP 这个场景。


六、安全边界（请认真读）
-----------------------
  · PIN 锁只挡「顺手翻看 / 肩窥」，不挡拆芯片。存的是 FNV-1a 混淆哈希，
    4 位 PIN 只有 1 万种，拿到 NVS dump 可离线爆破——这在设计预期之内。
  · 录入门户是开放网络（SoftAP 无密码），任何连上的人都能打开网页。
    录完之后请在设备上按 OK 退出门户，别让热点一直开着。
  · `/export` 是明文导出且没有 PIN 保护，用完请立刻转存并删除。
  · 加密备份的口令你自己定、你自己记。**丢了就解不开，没有后门。**
    口令太弱（4 位）等于没加密。


七、项目状态
-----------
  · M1（核心）：单账户取码 + 校时 + AP 录入 —— 已完成
  · M2（完整）：多账户 + PIN 锁 + 加密备份 + 导出 —— 已完成
  · 真机验收：**尚未执行**。全部功能都只有主机侧测试覆盖，
    与 Google Authenticator 的码值一致性还没在真机上比对过。

  · 已知缺口：加密备份只有导出，**还没有导入端**。设备丢了之后暂时无法
    从备份文件恢复，这是有意留的缺口，不是遗忘。
